# Dashboard tracking and human attestations

Use only when the local workflow profile configures a dashboard. Keep its workbook, index, source snapshots and human attestation evidence outside disposable job folders and outside publicly shareable skill packages. The local profile owns paths, identity and refresh commands.

At resumption, read the retained dashboard decisions before repeating review or acceptance questions. Sync saved human decisions through the configured local helper. Register new outputs/contracts in the existing journal, then refresh the dashboard before delivery; report refresh failures instead of silently omitting the row. Dashboard bookkeeping never authorizes media processing, new reviews, publication or deletion.

One row represents an exact revision package (possibly several clips and their projects). Bind its stable ID to the job, stage, checklist contract, requirements and registered output identities. Show the full human checklist and exact target IDs. Changed bindings create a new pending row; preserve old rows and history. Never carry a pass to changed media or manufacture historical passes when importing old work.

The owner's explicit `Passed - all listed checks performed` dropdown selection attests that every listed human check was performed using the shown method on all listed targets, with complete coverage. Preserve the actual saved workbook plus a structured attestation with provenance and import time. The sync helper records each applicable check as `human_verifier`, using this evidence and the existing review API. A checkbox alone without a displayed, frozen checklist and revision binding is insufficient. Do not invent additional observations. Full playback, framing and listening require entire-artifact coverage.

Human methods may include editorial, visual, metadata, package, playback, listening and project GUI inspection. They cannot replace automated_validation or project_comparison. Keep missing automated checks and other outstanding conditions visible. Mark production completed only through the existing stage gate; a human pass does not waive baseline, dependency, technical, evidence or blocking-issue requirements. A general changes request does not invent specific failed checks; supersede prior dashboard human passes as unverified when the owner retracts the pass.

Keep human verification, optional independent review choice, acceptance, closure and availability distinct. The workbook is authoritative for its editable human decisions; journal production state is authoritative for production completion. A saved attestation needs no AI call. Never programmatically select Passed on the user's behalf. Existing recorded acceptance is imported without inferring performed human verification.

Refreshes preserve edits by stable ID after sorting. Validate generated fields and inputs before import. Save edits durably before journal writes, make retries idempotent, and do not overwrite a workbook open for editing. Surface missing or changed targets as historical attestations without registering new current check passes. A deleted job stays listed, preserving historical decisions; availability is reported separately and no claim of present integrity is made. Keep original links as provenance, label missing paths, and never delete or silently drop records.

Sync outcomes distinguish `applied`, `historical_only`, `waiting_for_delivery`, and `waiting_for_change`. A decision waiting for delivery is not acknowledged as synced; registering the exact delivery permits retry. Persistent errors wait for changed journal/evidence conditions rather than repeating identical writes on every refresh. Earlier deferred decisions retain ordering. The shared completion evaluator checks blockers, recursive dependencies and review dispositions as well as integrity; refresh may take longer when media must be hashed. Hashes are reused only within one refresh audit. No recorded status or owner pass bypasses unresolved conflicting findings.
