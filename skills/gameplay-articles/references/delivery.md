# Article package

Register these files and the applicable `article` contract using the [structured review workflow](../../_video-shared/review-workflow.md). Bind producer checks to matching Markdown/HTML/SEO and screenshot revisions. Preserve the private editorial report and evidence for an optional reviewer; choosing human review does not record a pass or user acceptance. Notes-only scope and screenshot exemptions require explicit rationale; do not hide missing required coverage behind an exemption.

Write an isolated article job containing `article.md`, `article.html`, `seo.md`, `editorial-review.md`, `screenshots.json` and `images/`. Preserve approved revisions. Both article versions must match in substantive text, image order and headings.

Use one H1, a concise intro, optional quick verdict, TOC, useful H2 sections and an appropriate closing verdict. Do not force Pros/Cons into a tutorial or impose a fixed word count. Each H2 has a stable `section-N` anchor; TOC wording and order match all H2s including exempt sections. Markdown may use explicit HTML anchors. Place one image immediately after its eligible H2 unless the user requests another location. HTML uses relative img src, escaped alt text, and optional figure/figcaption. Markdown uses the same relative paths. Captions describe what is visible, not unsupported mechanics.

For HTML, use `../assets/toc.html` and repeat the li template once per H2, replacing the anchor and escaped heading. Preserve its inline styling unless the site profile requests a different style. Markdown uses a normal linked TOC. No guessed public image URLs; local paths are not CMS uploads.

For reviews/impressions, follow the site's Pros/Cons preference and verify it in both versions. Base each item on supported user impressions or clearly identified session limitations; do not invent criticism, force equal counts, or turn missing release information into a gameplay flaw. If the notes provide no supported drawback, say so within the scoped impressions or obtain the missing opinion; do not silently omit a required summary. Tutorials and news do not automatically need this structure.

Before final delivery, reconcile the outline against the actual package: every required section and its image or explicit exemption must be present in both formats. Open the final extracted image files, verify the relative links resolve from each article, and deliver the image folder with the prose. A timestamp list, planned extraction, or empty images directory is not screenshot delivery. Continue pending executable image work within the current request; hand off an incomplete draft only with the concrete blocker and remaining work identified.

Follow the selected site's approved CTA wording and placement. Never carry another site's services pitch into a new creator's article. Confirm article-specific disclosures from user input.

SEO package: primary keyword as an editorial suggestion, related terms naturally used, five relevant title alternatives, a concise meta description (aim 150–160 characters without padding), and verified internal links from available references. Do not claim search volume, rankings or a best-performing title without data. Do not force comparison/list titles onto unsuitable content.

The private editorial report contains potential disputes for manual resolution, unverified external facts, footage coverage limits, missing screenshots, exemption mapping and image provenance. Keep report annotations out of article prose. If omission leaves a section incomplete, mark that fact in the report and describe the article as a draft requiring manual review.

Before delivery check: matching Markdown/HTML content; unique working H2 anchors; TOC entry count; one existing image per non-exempt H2; exemptions documented; alt text; sources and internal links actually supported; site CTA included; no fabricated experience or disclosure. Record human visual checks separately from automated file checks. A missing appropriate image stays unresolved after targeted search and a user question.
